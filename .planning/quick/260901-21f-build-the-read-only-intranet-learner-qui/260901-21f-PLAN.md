# Internal intranet learner quiz-summary API

## Goal

Add a read-only internal GET endpoint for BMH me to retrieve a learner's final-quiz summary by email. Protect it with a fail-closed constant-time service-token check. Prove the focused tests can fail before restoring the correct implementation. Verify the full repository suite. Open a PR and leave it unmerged.

## Must haves

### Truths

- Missing, malformed, wrong, or server-unset bearer credentials receive an authentication rejection before any database query.
- A known learner receives exactly `email`, `bestFinalQuizScore`, `passed85`, `attempts`, and `lastAttemptAt` derived from completed final-quiz attempts.
- An unknown learner receives 404. A caller holding the internal service token can distinguish that response from a known learner's 200 response, so the token grants learner-existence lookup by design.
- The endpoint performs only service-role reads and has no mutation path.
- Focused tests have recorded red evidence from deliberate guard or summary mutations before the final green run.
- The branch is pushed and a PR is opened with `Depends on: none`; the PR is never merged.
