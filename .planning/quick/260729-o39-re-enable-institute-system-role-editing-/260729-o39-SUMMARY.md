# Institute role editing summary

## Delivered

- Removed the obsolete all-role equality guard from the per-user editor.
- Restored the role-group RPC, profile role write, and role-group compensation
  path.
- Moved the exact `profiles.system_role` write to the service-role client after
  `requireAdmin()`. Migration 025 permits the signed-in client to update only
  `full_name` and `avatar_url`.
- Updated the separate `updateUserRole` action to use the same trusted role
  write and to reject a missing target instead of returning false success.
- Preserved owner self-demotion protection. Also blocked admin self-promotion
  and allowed an admin to save their own role groups when their role is
  unchanged.
- Preserved enrollment email diffing and release-control error normalization.
- Changed no migration file.

## Adversarial findings

- Refuted the literal "delete the guard" patch. Commit `9fdd618` had also
  removed the real profile update, so deleting only the guard would have
  returned success without changing the role.
- Refuted the assumption that the users-list action already worked against the
  database. Migration 025 revokes authenticated `system_role` updates. Its unit
  test mocked a permission the signed-in client does not have.
- Refuted the claim that the two confirmed preconditions fully establish
  durable Institute role ownership. The latest Hugo lifecycle wrapper still
  calls `hugo_apply_access_unhashed`, which can write its role back to
  `profiles.system_role` during later grant, suspend, or reactivate operations.
- Owner safety still requires `hugo_access_grants.role = 'owner'`. A person
  promoted only in Institute can sign in but may not count as a usable owner.
- The preserved application compensation is not atomic. A concurrent role-group
  edit can be overwritten by a later rollback. Fixing this requires one
  transaction-backed database operation.

## Blocker

The application-only changes make immediate role writes real and make both
exports consistent. They do not make Institute role ownership durable across
later Hugo lifecycle operations. Correcting that contract and making the
combined role plus role-group save atomic require database work, which this
task prohibits. PR #137 must not merge until Claude decides how to resolve or
explicitly bound those gaps.
